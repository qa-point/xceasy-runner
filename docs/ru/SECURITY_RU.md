# Политика безопасности

[English](../en/SECURITY_EN.md) · Русский

Исправления безопасности выпускаются для последнего опубликованного релиза. Для старых preview-версий может потребоваться обновление; отдельной ветки долгосрочной поддержки нет.

## Сообщить об уязвимости

Используйте [закрытый канал GitHub](https://github.com/qa-point/xceasy-runner/security/advisories/new). Укажите версию, последствия и минимальное воспроизведение на синтетических данных. Не размещайте пароли, токены, приватные скриншоты UI и клиентские логи в публичных issues. Если закрытый канал недоступен, создайте issue с просьбой предоставить приватный контакт без деталей уязвимости.

## Диагностика

XCEasy — тестовый фреймворк: дерево UI, значения полей и скриншоты помогают разбирать ошибки и могут содержать данные приложения. Для синтетических данных сохраняйте полезную диагностику. Существующий текстовый фильтр учётных данных работает по ограниченным правилам и не гарантирует обезличивание. Управляйте доступом и сроками хранения отчётов; не считайте скриншоты автоматически обезличенными.

## Защита репозиториев и сборки

Actions закреплены commit SHA и обновляются через Dependabot. Security workflow проверяет достижимую Git-историю Gitleaks 8.30.1 с закреплённой checksum архива; версию сканера и checksum следует обновлять вместе после проверки. Для ложных срабатываний допустимы только точечные документированные fingerprints; реальные секреты нужно отзывать, а не исключать из проверки.

Secret scanning, push protection, закрытые сообщения, правила веток/тегов и автоматические исправления зависимостей включаются в настройках GitHub отдельно от этих файлов. Обновления зависимостей требуют проверки и успешного CI. Сборочные jobs имеют только чтение репозитория; публичные зависимости не требуют персонального integration token.
