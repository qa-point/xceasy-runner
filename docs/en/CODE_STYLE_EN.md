# XCEasy Runner code style

- Scripts use strict mode, quoted variables, explicit exit codes, temporary directories, and atomic replacement for contract artifacts.
- Prefer small scripts with one input/output contract. Stable JSON keys use `snake_case`; reason codes use lowercase dot notation.
- Never parse localized prose when structured data exists. Never use fixed sleeps for readiness.
- Resolve destructive targets explicitly and never remove a user-provided broad directory.
- New behavior requires positive, negative, and malformed-input fixtures. Parallel changes require isolation and duplication checks.
- Comments explain decisions or invariants. Public commands and schemas require RU/EN examples.
